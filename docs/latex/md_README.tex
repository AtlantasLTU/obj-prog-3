\hypertarget{md_README_autotoc_md25}{}\doxysubsubsection{\texorpdfstring{Pastebėjimai}{Pastebėjimai}}\label{md_README_autotoc_md25}
Ta pati programa perdaryta su class tipu lėtesnė \texorpdfstring{$\sim$}{\string~}3x negu su struct, priklausomai nuo optimzacijos vėliavėlės. Taip yra todėl, kad class tipo programoje, galutinis balas skaičiuojamas, kai jo prireikia ir nėra saugojamas atminty, tai sutaupo atminties, tačiau padidina skaičiavimų laiką. Pagrinde -\/Ofast vėliavėlė greičiausia, tačiau esant milijonui studentų -\/O3 aplenkia -\/Ofast vėliavėlė, galbūt -\/O3 geriau suoptimizuoja failų skaitymą. Mažiausią failą sukuria -\/O1 vėliavėlė, o didžiausią -\/O3. Taip yra todėl, kad -\/O1 skirtas balansui tarp greičio ir dydžio, o -\/O3 skirtas našesniam programos veikimui.

Nors struct tipas greitesnis, tačiau class tipas saugesnis ir plečiant programos apimtį, enkapsuliacija, paveldamumas ir kitos class tipo ypatybės padaro jį naudingesniu.\hypertarget{md_README_autotoc_md26}{}\doxysection{\texorpdfstring{Relizų aprašas}{Relizų aprašas}}\label{md_README_autotoc_md26}
